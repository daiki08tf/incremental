# ゲーム設計書(GDD) — 漂流コロニー(仮)

## 0. 概要

| 項目 | 内容 |
|---|---|
| ジャンル | ブラウザ用インクリメンタル(放置)ゲーム |
| 技術 | Vanilla JS / HTML / CSS(フレームワーク不使用) |
| 世界観 | RimWorld 風。辺境惑星への墜落コロニー再建 |
| タイトル案 | 『漂流コロニー -Ashfall-』(仮。要調整) |
| 数値スケール | 〜10^15 程度。JS標準 Number でOK(多倍長数値ライブラリ不要) |
| ビジュアル | 絵文字/記号は使わずCSSのみで描くドット絵風UI |

---

## 1. 世界観・ストーリー

輸送船「エンバー号」が航路を外れ、名も無い辺境惑星に墜落する。生き残った漂流者たちは
瓦礫の中から資源を集め、仮設の拠点をコロニーへと育てていく。最終目標は、集めた資材で
新しい**脱出船**を組み上げ、次の(より過酷な/より豊かな)惑星へと旅立つこと。

- 1周目: 何もない荒野からのサバイバル
- 惑星ジャンプ(プレステージ)のたびに、コロニーは失われるが「知識」と一部の生存者は
  引き継がれ、次の惑星ではより早く・より効率的に再建できる
- 惑星ごとに簡単なフレーバー(環境ボーナス/ペナルティ)を持たせ、周回に変化を出す

物語は凝った会話イベントなどは持たず、実績・ログテキスト・惑星到着時のフレーバー文で
最低限の空気感を出す(MVPでは簡素、余力があれば拡充)。

---

## 2. コアループ

1. **クリック採集**: 「木材を集める」ボタンを手動クリックして初期資源(木材)を得る
2. **建物購入**: 木材/金属を使って自動生産施設を建てる → 放置で資源が増える
3. **アップグレード**: 建物レベルアップ、クリック効率強化、生存者の割り当て
4. **中盤資源の解放**: 金属・食料・電力・部品が順番にアンロックされ、生産チェーンが広がる
5. **脱出船建造**: 部品と金属を大量に集めて脱出船を完成させる
6. **惑星ジャンプ(プレステージ)**: リセットして知識ポイントを獲得、永続強化を購入
7. 2周目以降は初期ブーストが効くため、テンポよく1周目より早く6まで到達する

---

## 3. 資源

| 資源 | 入手方法 | 用途 | 解放タイミング |
|---|---|---|---|
| 木材 (Wood) | 手動クリック / 伐採小屋 | 初期建物の購入 | 最初から |
| 金属 (Metal) | 採掘機(木材で建設) | 建物アップグレード、部品精製 | 序盛(建物1〜2個目) |
| 食料 (Food) | 農場(開始時に非常食30) | 生存者の維持(不足すると生産全体にペナルティ) | 生存者が増え始めるタイミング |
| 電力 (Power) | 発電機 | 上位施設の稼働(貯蔵はせずキャパシティ制) | 中盤 |
| 部品 (Components) | 精製所(金属+電力を消費) | 上位アップグレード・脱出船建造 | 中盤以降 |
| 知識ポイント (Knowledge) | プレステージ時に部品蓄積量に応じて獲得 | 永続強化ツリー購入 | プレステージ後 |

食料が枯渇すると生存者の作業効率が一時的に低下する(ゲームオーバーにはしない、
インクリメンタルとしてのテンポを損なわないため)。電力は「発電量 ≥ 消費量」で
稼働、不足時は稼働率が比例縮小する(RimWorldのブラウンアウト風)。

---

## 4. 建物(自動生産施設)

| 建物 | 生産 | 消費 | 備考 |
|---|---|---|---|
| 伐採小屋 | 木材/秒 | なし | 最初の建物 |
| 採掘機 | 金属/秒 | なし | 木材で購入 |
| 農場 | 食料/秒 | なし | 生存者維持用 |
| 発電機 | 電力/秒(供給) | 木材 or 金属 | 電力キャパシティを増やす |
| 精製所 | 部品/秒 | 金属+電力 | 上位資源の生産チェーン |
| 通信塔 | (実績/イベント関連の解放) | 電力 | フレーバー枠、任意で拡張 |

- 各建物は個別にレベルアップ可能。コストは指数関数的に増加:
  `cost(n) = baseCost * growthRate^n`(growthRate は 1.12〜1.15 目安、資源ごとに調整)
- 生産量: `output(n) = baseOutput * n * (1 + upgradeBonus)`(シンプルな線形+乗算ボーナス)
- 建物ごとにマイルストーン的な「〇〇個到達で生産倍化」などのボーナスを軽く入れて
  マンネリを防ぐ(任意、MVP後の拡張候補)

---

## 5. 生存者システム(簡略版)

RimWorldらしさを出すための軽量な要素。個別AIや詳細な気分システムは持たず、
「人数」と「割り当て」だけを扱う:

- 一定の資源/実績条件で生存者が増える(上限あり、上限は永続強化で拡張)
- 生存者は建物に割り当てることで、その建物の生産に軽いボーナス(+割り当て人数に応じた%)
- 生存者は食料を1人あたり一定量消費する
- プレステージ時、**最大3人まで**次の惑星に連れて行ける(ハイブリッド仕様の片翼)。
  連れて行った生存者はそのまま次周でも割り当て済みの状態でスタートできる

---

## 6. プレステージ:「惑星ジャンプ」

- 発動条件: 脱出船の建造完了(部品・金属を規定量集めてボタンを押す)
- リセット対象: 資源(木材・金属・食料・電力・部品)、建物レベル、未連れ出しの生存者
- 引き継ぐ要素(ハイブリッド):
  1. **知識ポイント(KP)**: ジャンプ時に蓄積した部品総量に応じて獲得。KPは永続強化ツリーで
     消費(全生産+X%、初期資源ボーナス、生存者上限+1、食料消費-X% など)
  2. **選抜生存者**: 最大3人を選んで同行させる(装備/スキルは簡易ステータスとして保持)
- 惑星バリエーション: ジャンプ先の惑星ごとに簡単な環境修飾(例:「凍土惑星: 食料生産-20%、
  金属産出+20%」)をランダム or 順送りで付与し、周回に変化を持たせる(MVP後の拡張候補。
  MVPでは固定の環境で構わない)

---

## 7. 実績システム

- 進行のマイルストーンごとに実績を解放(初採集、初建物、初プレステージ、生存者N人、
  資源蓄積量、周回数など)
- 実績は小さな永続ボーナス(クリック効率+1%など)を与える
- 実績の保有状態は **LocalStorageにのみ保存**し、セーブコードには含めない
  (コードを短く保つためのハイブリッド仕様。他端末で読み込んだ場合、実績は
  その端末側の記録がそのまま使われる="実績はその端末のプレイ記録"という扱い)

---

## 8. オフライン進行

- 最終アクセス時刻を保存し、再訪問時に経過秒数から放置生産分をまとめて計算
- オフライン効率は100%未満(例: 50%)にして、プレイ中との差別化をする
- 上限時間を設定(例: 最大8時間分まで)し、青天井の放置を防ぐ
- 復帰時に「〇時間分の生産がありました」というサマリーをモーダル表示

---

## 9. セーブシステム(自動保存 + セーブコード併存)

### 9-1. 自動保存(LocalStorage)
- 一定間隔(例: 10秒ごと)で全状態をJSONとしてLocalStorageに保存
- 実績・設定・惑星到達履歴などの「細かい記録」もここに保持

### 9-2. 「ふっかつのじゅもん」型セーブコード
- 精度優先(ユーザー要望どおり、数値は丸めずそのまま保持)としつつ、
  文字数を実用的な範囲に抑えるため以下の方式を採る:
  1. 保存対象を主要パラメータに絞る: 各資源量、各建物レベル、生存者数と割り当て、
     KP、惑星ジャンプ回数、連れ出した生存者情報、最終セーブ時刻
     (実績・設定などの副次データはコードに含めない = 9-1と役割分担するハイブリッド)
  2. これらを固定順の配列にシリアライズ → 数値は36進数文字列化(10進より短い)
  3. 区切り文字を最小限にしたコンパクトなフォーマットに結合 → Base64url相当の
     文字セットでエンコード
  4. 末尾に簡易チェックサム(1〜2文字)を付与し、誤入力を検出
  5. 想定文字数: 中盤程度の状態で概ね 40〜80文字程度(RimWorld要素を含む分、
     ふっかつのじゅもん本家より長くなるが、コピペ1回で収まる範囲を目標とする)
- UI: 「コードを発行」ボタンでテキスト表示+コピー、「コードを読み込む」で入力→復元
- コード発行時、実績など副次データは移らない旨を軽く注記する

---

## 10. UI / ビジュアル方針

- 画像素材・絵文字は使わず、CSSの矩形・グラデーション・box-shadowでドット絵風の
  アイコン(木材の山、歯車、稲妻など)を表現
- カラーパレットは荒廃した惑星らしい、くすんだアース系+アクセントカラー1〜2色
- レイアウト: 左に資源/生存者パネル、中央にクリック採集エリア、右に建物リスト、
  下部にログ/実績通知(スマホ幅では縦積みに切替)

## 11. 技術構成(想定ファイル構成)

```
/
├── index.html
├── style.css
├── src/
│   ├── main.js          (ゲームループ、初期化)
│   ├── state.js          (ゲーム状態の定義・初期値)
│   ├── resources.js       (資源の生産/消費計算)
│   ├── buildings.js      (建物データ・購入/アップグレード処理)
│   ├── survivors.js      (生存者の増加・割り当て)
│   ├── prestige.js       (惑星ジャンプ処理・永続強化)
│   ├── achievements.js   (実績定義・判定)
│   ├── save.js           (LocalStorage保存/読込、セーブコードのエンコード/デコード)
│   └── ui.js             (DOM描画・イベントバインド)
└── docs/
    └── GDD.md            (このファイル)
```

ビルドツールは使わず、分割したファイルをそのまま `<script>` で読み込む想定
(依存ゼロ、`index.html` を開くだけで動作)。当初 `<script type="module">` を
想定していたが、`file://` で直接開くとブラウザのCORS制限でモジュールが
読み込めないため、各ファイルが `window.Game` という共有オブジェクトに
機能を生やしていく素朴な名前空間パターンに変更している(読み込み順は
`index.html` 内の `<script>` の並び順に依存)。

## 12. 開発スコープ(MVP → 拡張)

**MVP(最初の実装ターゲット)**
- 資源: 木材・金属・食料・電力・部品
- 建物: 伐採小屋・採掘機・農場・発電機・精製所(各レベルアップ可能)
- クリック採集 + 生存者(増加・割り当てのみ、簡易ステータス無し)
- 脱出船建造 → プレステージ(KP永続強化 + 生存者3人同行)
- 実績 10〜15個程度
- オフライン進行(上限8時間、効率50%)
- LocalStorage自動保存 + セーブコード発行/読込
- CSSドット絵風の最低限のUI

**拡張候補(MVP後)**
- 惑星ごとの環境修飾バリエーション
- 生存者個別スキル・装備の深掘り
- 襲撃イベントなどのランダムイベント
- 実績によるフレーバーテキスト/ログの充実
- サウンド、アニメーション演出

## 14. MVP実装メモ(2026-09時点)

設計を踏まえて実際に動くMVPを実装した。ヘッドレスブラウザ(Playwright)で
クリック採集/建物購入/自動生産/生存者受け入れ/セーブコードの往復/破損検知/
プレステージ/LocalStorage永続化の一通りを動作確認済み。

実装時に決めた具体的な数値(バランス調整の出発点、`src/*.js` 内の定数):

- 建物コスト増加率: 1.13〜1.16(建物ごとに微妙に変えて後半building間の
  コスト差を出している)
- 生存者1人あたりの食料消費: 0.15/秒、割り当てボーナス: 建物ごとに
  割り当て人数×8%の生産アップ
- 生存者受け入れコスト: `20 * 1.5^現在人数` 木材、上限は基本5人+永続強化
- 脱出船(プレステージ)条件: 部品500・金属800。知識ポイント獲得量は
  `floor(sqrt((部品*2+金属)/40))`(下限1)
- 永続強化: 生産効率+5%/lv、開始時木材+100/lv、生存者上限+1/lv、
  食料消費-8%/lv(それぞれ上限レベルあり)
- オフライン進行: 最大8時間分、効率50%
- セーブコード: 資源・建物レベル・生存者・プレステージ状態を36進数化し
  `.`区切り+チェックサムで連結。実際の生成コードは60〜70文字程度
  (目標レンジ40〜80文字に収まっている)。実績・累計統計はコードに含めず
  LocalStorageのみに保存

実装上の簡略化(GDDからの変更点):
- 電力は「貯蔵する資源」ではなく毎tick再計算する瞬間の需給値として扱う
  (発電不足時は電力を使う建物の稼働率を按分で下げる)
- 食料切れ時のペナルティは段階的な計算ではなく「在庫0なら生産全体を
  50%に低下」という単純な閾値判定
- プレステージの持ち越し生存者は個体差(装備・スキル)を持たせず、
  「人数」のみを引き継ぐ簡易実装

デバッグで見直した点(2026-09):
- 発電機・精製所は投入資源(木材・金属)の在庫が足りない分だけ稼働率が下がる
  (以前は在庫0でも生産し続けていた)
- 開始時に非常食30を持ち、農場は木材40だけで建てられる
  (以前は最初の生存者を迎えた瞬間に飢餓になっていた)
- オフライン進行は30秒刻みで分割して計算する(途中で資源が尽きる状況を再現)
- 建物コストは整数に切り上げ
- 描画はDOMを作り直さず値だけ更新する方式に変更(スマホでタップが通らない問題の修正)
- 確認はブラウザの confirm/alert ではなくページ内モーダルで行う
- アーティファクト版 `artifact/game.html` は `scripts/build-artifact.sh` で生成する
